# RFP Scoring

Help score consultant submissions against the RFP evaluation criteria using fair, evidence-based evaluator notes.

## Use these references

Read only what is needed:
- `references/barrie-strategic-plan-rfp-template.md` when scoring FIN2026-064P Barrie Transit Strategic Plan submissions.

When writing for Mike, read the `personal_context` MCP resources for writing style if available:
- `portfolio://communication-style`
- `portfolio://preferences-and-constraints`

## Default scope

Unless Mike asks otherwise:
- Score Section F technical criteria only.
- Use Appendix D / Section A as the scope reference.
- Score each submission independently.
- Do not compare proponents.
- Do not review pricing.
- Do not calculate weighted points, section totals, technical totals, or award rankings.
- Do not edit the Excel workbook unless Mike specifically asks.
- Provide suggested scores only. Mike makes the final evaluator decision.

## Before scoring

1. Read the RFP, all addenda, the evaluation workbook, and the submission files.
2. Treat addenda as controlling where they update the original RFP.
3. Confirm the exact scored rows from the workbook.
4. Review the proposal evidence for each row.
5. Do not infer evidence that is not shown in the submission.
6. If a required submission file is missing, ask for it or flag the affected scoring rows as not assessable.

For FIN2026-064P, score these exact worksheet input rows:

## Scoring scale

Use this scale exactly:
- 0-1 = Unsatisfactory / no acceptable response
- 2-3 = Poor / response is minimal
- 4-5 = Weak / partially meets requirements
- 6-7 = Good / meets minimum requirements
- 8-9 = Very Good / exceeds minimum requirements
- 10 = Excellent / exceeds minimum requirements in multiple areas

## Band rules

- Use the lower score in a band when evidence is thin, vague, or only partly supported.
- Use the higher score in a band when evidence is clear, specific, and well supported.
- Minimum-only responses normally stay at 6-7.
- Use 8-9 only when the submission clearly goes beyond the minimum requirements.
- Use 10 only when the submission exceeds requirements in multiple clear areas.
- Missing or unclear evidence is a gap. Do not give benefit of the doubt.
- A polished proposal should not receive a high score unless the evidence supports it.

## Output format

Use this format for each row:

```text
F.2b Project Manager
Suggested score: X/10

Minimum:
- ...

Preference:
- ...

Improvement:
- ...
```

If needed, add:

```text
Red flags:
- ...
```

Only include red flags when there are material gaps, risks, or unclear items.

## Comment style

Write like evaluator notes for a worksheet:
- Point form.
- Short and practical.
- Plain language.
- Direct wording.
- No long paragraphs.
- No filler.
- No AI-sounding summary language.
- No consultant-style wording.
- Use evidence from the submission.
- Mention numbers, dates, roles, project names, or percentages when they matter.
- Keep comments suitable for paste-in to the workbook.

Avoid words and phrases like:
- robust
- innovative
- comprehensive
- cutting-edge
- leverage
- demonstrates a deep understanding
- uniquely positioned
- best-in-class
- it may be advisable

Prefer wording like:
- Shows...
- Provides...
- Identifies...
- Includes...
- Does not show...
- Missing...
- Unclear whether...

## Review method

For each worksheet row:
1. Identify the required information from Section F.
2. Check whether the proposal meets the minimum requirements.
3. Check whether the proposal includes preference-level evidence.
4. Note practical gaps or areas that weaken the score.
5. Assign a suggested 1-10 score using the scale.
6. Keep the score aligned with the comments.

## Fairness rules

- Apply the same evidence standard to each proponent.
- Do not use knowledge from another proponent when scoring the current one.
- Do not penalize a proponent for not offering something that was not requested.
- Do not reward vague claims unless supported by specific evidence.
- Do not treat firm reputation as evidence unless the submission connects it to this project.
- If a criterion asks for current or recent project examples, check dates and completion status.
- If the proposal gives contradictory information, flag it plainly.

## When Mike asks for less than the full review

If Mike asks for one section, only score that section.
If Mike asks for gaps only, do not provide scores unless requested.
If Mike asks for a comparison later, make a separate comparison after the independent scoring is complete.
